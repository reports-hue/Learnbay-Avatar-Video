## Task: Fix Caption Sync Using Azure Speech SDK Word Boundary Events

### What to fix
Captions are currently timed by character count or fixed duration splits — they run too fast or too slow and never align with the actual voice. Fix this by using Azure Speech SDK word boundary events to collect exact per-word timestamps during TTS synthesis, then use those timestamps to drive the ASS subtitle file.

## Implementation: Azure Speech SDK Word Boundaries

1. Ensure microsoft-cognitiveservices-speech-sdk is installed in api-server

2. During TTS synthesis, attach a wordBoundary event listener to the synthesizer:
   - e.audioOffset = start time in ticks → divide by 10_000_000 to get seconds
   - e.duration = word duration in ticks → divide by 10_000_000 to get seconds
   - e.text = the word string
   Collect all events into: { word: string, startSeconds: number, durationSeconds: number }[]

3. After synthesis completes, group words into caption chunks of 3-5 words maximum:
   - chunk startTime = first word's startSeconds
   - chunk endTime = last word's startSeconds + last word's durationSeconds

4. Write chunks into the ASS subtitle file. Every Dialogue: line must use real start/end from SDK data.

5. Return both the audio file path AND the word timestamps array from the TTS service so the ASS generator can consume them.

6. If word boundary events are empty (fallback), throw an error — do NOT silently fall back to estimated timing.

---

## ASS Subtitle File Rules

- Max 5 words per caption line
- White bold text, clean sans-serif (Arial or similar)
- BorderStyle 1 — outline + shadow only. No opaque box background
- Caption position: lower-center of frame, above CTA zone
- Every Dialogue line start/end time comes from SDK word boundary data — never calculated
- Add 50ms gap between consecutive caption chunks to prevent them running together
